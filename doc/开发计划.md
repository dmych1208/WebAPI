## Phase 0: 项目初始化与基础框架 (Day 1-2)

### Day 1 — 项目创建与骨架搭建

**目标**：能编译运行的空壳程序，包含主窗口和标签页框架。

- [ ] **P0-001** 创建 .NET 8 WPF 项目 `WebAPI.sln`
  - 项目名：`WebAPI`
  - 目标框架：`net8.0-windows`
  - NuGet 引入：
    - `Microsoft.Web.WebView2` (最新稳定版)
    - `CommunityToolkit.Mvvm` (可选，MVVM辅助)
    - `Newtonsoft.Json` 或使用内置 `System.Text.Json`
  
- [ ] **P0-002** 搭建目录结构
  ```
  src/
  ├── WebAPI/           # 主程序
  │   ├── Controls/     # 自定义控件 (ChannelPanel 等)
  │   ├── Adapters/     # 适配器
  │   ├── Common/       # 公共组件
  │   └── Models/       # 数据模型
  ├── log/              # 日志目录 (gitignore)
  └── doc/              # 文档目录
  ```

- [ ] **P0-003** 实现多标签页主窗口骨架
  - `MainWindow.xaml` — TabControl + 状态栏
  - TabItem 动态生成（从配置读取渠道列表）
  - 每个 TabItem 内容 = `ChannelPanel` UserControl
  - 标签样式：图标 + 名称 + 状态指示灯

- [ ] **P0-004** 实现 ChannelPanel 控件布局
  - 左右分栏 Grid (3* : 320px)
  - 左侧：WebView2 占位区域 + 底部输入栏叠加层
  - 右侧：StackPanel 包含状态区/API区/模型列表/日志区/按钮区
  - 参考截图的深色主题配色方案

- [ ] **P0-005** 配置管理器 `Config.cs`
  - 读取 `config/settings.json`
  - 渠道列表解析为 `List<ChannelConfig>`
  - 配置变更监听（FileSystemWatcher 或手动刷新）

**交付物**：可编译运行的主窗口，显示空标签页

### Day 2 — HTTP服务 + SSE解析 + 日志系统

**目标**：HTTP服务器能接收请求并返回模拟响应，日志系统正常工作。

- [ ] **P0-006** 实现 `HttpServer.cs`
  - 基于 `HttpListener` 的异步HTTP服务器
  - CORS 头处理 (`Access-Control-Allow-Origin: *`)
  - OPTIONS 预检请求处理
  - 路由分发：`/v1/chat/completions`, `/v1/models`, `/health`, `/shutdown`
  - 每个渠道独立端口实例

- [ ] **P0-007** 实现 `RequestParser.cs`
  - 解析 OpenAI 格式 JSON 请求体
  - 提取 model / messages (system+user) / stream / temperature / max_tokens
  - 合并 system prompt 为前缀

- [ ] **P0-008** 实现 `ResponseConverter.cs`
  - 构建 OpenAI 兼容格式的响应JSON
  - 流式响应：SSE格式 (`data: {...}\n\n`)
  - 非流式响应：完整JSON对象
  - 生成唯一 `chatcmpl-xxx` ID
  - 时间戳字段填充

- [ ] **P0-009** 实现 `SseParser.cs`
  - 原始SSE流 → 结构化事件
  - 处理 `event:` / `data:` 行
  - 内部消息过滤（status/token_usage/title/update_session/search_result）
  - content 字段提取（支持 v/content/delta 多种字段名）
  - 缓冲区管理（处理不完整的行）

- [ ] **P0-010** 实现 `LogManager.cs`
  - 输出到 `log/YYYY-MM-DD.log`
  - 格式：`[HH:mm:ss] [LEVEL] message`
  - 级别：DEBUG / INFO / WARN / ERROR
  - 控制台 + 文件双输出
  - 自动清理 >30天的旧日志
  - 线程安全（lock 或 ConcurrentQueue）

- [ ] **P0-011** 定义 `IAdapter.cs` 接口
  ```csharp
  public interface IAdapter {
      string TargetUrl { get; }
      string PlatformId { get; }
      int Port { get; }
      string UserDataFolder { get; }
      List<ModelInfo> AvailableModels { get; }
      string GetNetworkInterceptorScript();
      string GetDomControlScript();
      Task InjectPromptAsync(WebView2 webView, string prompt);
      SseEvent? ParseSseData(string rawLine, ref string lastEventType);
  }
  ```

- [ ] **P0-012** 创建 `config/settings.json` 默认配置文件
  - 三个渠道的默认配置（DeepSeek/千问/豆包）
  - 端口、URL、模型列表

- [ ] **P0-013** 创建 `.gitignore`
  - 忽略 `log/`、`bin/`、`obj/`、`.vs/`
  - 忽略用户敏感配置（如含token的settings.json.local）

**交付物**：HTTP服务器可用 curl 发请求并获得模拟响应；日志正常写入 `log/` 目录

### Day 4 — DeepSeek WebView2 集成与对话流程

- [ ] **P1-006** 实现 WebView2 初始化流程
  - 创建独立的 CoreWebView2Environment（指定 UserDataFolder）
  - EnsureCoreWebView2Async 异步等待
  - 注入网络拦截脚本 (`AddScriptToExecuteOnDocumentCreatedAsync`)
  - 注册 WebMessageReceived 事件
  - 导航到目标URL
  - 监听 NavigationCompleted 事件确认页面加载完成

- [ ] **P1-007** 实现请求→注入→拦截→返回 的完整链路
  ```
  HTTP POST 收到请求
    → RequestParser 解析出 prompt
    → DeepSeekAdapter.InjectPromptAsync() 写入输入框并发送
    → WebMessageReceived 收到 NETWORK_DATA
    → SseParser 解析有效内容
    → ResponseConverter 转换为 OpenAI 格式
    → 写入 HttpListenerResponse (流式或非流式)
    → 收到 NETWORK_DONE → 结束响应
  ```

- [ ] **P1-008** 实现流式响应管道
  - 请求排队机制（ConcurrentQueue + 信号量，同一时间只处理一个请求）
  - SSE chunk 逐条写入 Response.OutputStream
  - Flush 确保实时性
  - 超时处理（60s无数据则中断）

- [ ] **P1-009** 实现非流式响应模式
  - 收集所有 SSE chunk 到 StringBuilder
  - NETWORK_DONE 后一次性返回完整 JSON
  - 设置正确的 Content-Type

- [ ] **P1-010** 错误处理
  - WebView2 未就绪时返回 503
  - 页面未登录时返回特定错误码和信息
  - 注入失败重试（最多2次）
  - 网络超时处理
  - 所有错误以 OpenAI error format 返回

**交付物**：能用 curl 向 localhost:55555 发请求并获得真实 DeepSeek 回复

## 风险与依赖

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 目标网页DOM结构变更导致适配器失效 | 高 | 将JS脚本外置为可编辑文件，方便快速修复 |
| WebView2内存占用过高 | 中 | 提供"重启浏览器内核"按钮；定期清理 |
| 某平台反自动化检测 | 高 | 模拟真实用户行为间隔；设置合理User-Agent |
| .NET 8 Runtime 用户未安装 | 低 | 发布时选择 self-contained 模式 |
| 千问/豆包需要登录才能用 | 中 | UI上提示登录状态；首次引导登录 |
